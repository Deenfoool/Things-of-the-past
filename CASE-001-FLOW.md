# Дело №001 — граф расследования

Кейс: `lyublino-1994`  
Источник фактов: `CASE-001-SOURCES.md`

Этот файл описывает **порядок открытия знаний игроком**, а не историческую хронологию.

## Обозначения

- `MUST` — обязательный узел для завершения дела;
- `OPTIONAL` — необязательная ветка, расширяющая понимание;
- `CLAIM` — показание/версия, не установленный факт;
- `ESTABLISHED` — установленное знание игрока;
- `FICTION_BRIDGE` — художественная игровая связка между подтверждёнными историческими фактами;
- `LOCK` — условие разблокировки;
- `SOFTLOCK-GUARD` — резервный способ получить обязательную информацию.

---

# Фаза 0. Получение дела

## N000 — сообщение дежурного `MUST`

Игрок получает только:

- дата: 24 августа 1994;
- время: около полудня;
- место: Люблинский рынок;
- сообщение о стрельбе;
- один погибший;
- один раненый;
- личности и обстоятельства пока неизвестны.

### Открывает

- локацию `market-main`;
- карточку события на доске;
- запись дела №001 в папке.

### Запрещено открыть здесь

- Владимир Жданов;
- Алексей Архипов;
- Андрей Малинкин;
- ПМ;
- точное число выстрелов;
- мотив;
- «Нико»;
- Сочи;
- судебный итог.

# Фаза 1. Прибытие на рынок

## N100 — торговая зона `MUST`

Игрок впервые прибывает на Люблинский рынок.

На этом этапе нейтральные hotspot'ы дают только атмосферные наблюдения и географию сцены.

### Возможные действия

- осмотреть основные прилавки;
- осмотреть боковую торговую зону;
- увидеть административную сторону;
- пройти во двор;
- пройти к кабинету директора.

Никакой случайный декоративный объект не должен автоматически выдавать имя погибшего или подозреваемого.

## N110 — работник рынка `OPTIONAL / FICTION_BRIDGE`

NPC работника рынка может существовать как композиционный свидетель, но до источниковой привязки его диалог не должен добавлять канонические факты.

Позднее этот NPC можно использовать как составного неназванного свидетеля только для сведений, которые прямо присутствуют в источниках, например наблюдения об уходивших людях. Такие реплики должны быть помечены как художественная реконструкция свидетеля, а не как цитата реального человека.

# Фаза 2. Кабинет директора — установление погибшего

## N200 — первичный осмотр мужчины `MUST`

Hotspot: `director-office-seated-victim`.

Первое взаимодействие сообщает только:

- взрослый мужчина;
- признаков жизни нет;
- он находится за рабочим столом/в кабинете администрации;
- необходима идентификация личности.

Добавляется факт:

`victim-present-unknown = ESTABLISHED`

Не добавлять имя автоматически.

## N210 — криминалист `OPTIONAL`, затем `MUST` для криминалистической ветки

NPC: `director-office-criminalist`.

На первом этапе криминалист не должен произносить точное число выстрелов или окончательное заключение.

Разрешённая безопасная реплика:

> Предварительный осмотр идёт. Сначала установите личность и соберите обстановку, точные выводы будут после фиксации.

Это `FICTION_BRIDGE`, а не историческая цитата.

Позы NPC:

- осматривает погибшего;
- делает записи;
- обернулся;
- обдумывает.

## N220 — служебный документ / идентификатор `MUST / FICTION_BRIDGE`

Игрок осматривает рабочий стол или документы.

Публичные источники подтверждают, что погибший — Владимир Жданов, директор рынка, но не описывают конкретный документ, по которому его идентифицировали в первые минуты. Поэтому игровой носитель допускается как художественная связка.

Предпочтительный вариант:

**служебная карточка/рабочий документ администрации**, на котором указано:

- Владимир Жданов;
- директор Люблинского рынка.

При первом чтении создаётся не окончательный факт личности, а зацепка:

`desk-name-vladimir-zhdanov = CLAIM`

Текст интерфейса:

«На рабочем документе указано имя Владимир Жданов. Нужно подтвердить, что документ принадлежит погибшему.»

## N230 — подтверждение личности `MUST`

Условие:

- открыт `desk-name-vladimir-zhdanov`;
- затем игрок повторно взаимодействует с криминалистом или получает подтверждение от сотрудника администрации.

Результат:

- `victim-zhdanov = ESTABLISHED`;
- `victim-director = ESTABLISHED`.

После этого:

- папка: «Владимир Жданов — погибший, директор Люблинского рынка»;
- карточка доски «Погибший» заменяется/обновляется, а не дублируется;
- хронология получает событие «Установлена личность погибшего».

### SOFTLOCK-GUARD

Если игрок не нажал документ, но несколько раз поговорил с криминалистом/осмотрел тело, криминалист мягко направляет:

«Посмотрите рабочие бумаги. Нужно сначала подтвердить, кто находился в кабинете.»

Криминалист **не выдаёт имя сам**, пока игрок не нашёл документ.

# Фаза 3. Первичная криминалистика

Разблокируется только после `victim-zhdanov`.

## N300 — предварительный осмотр ранений `MUST`

Источники S3/S4 позднее описывают два попадания — в область груди и горла. Это не должно быть известно игроку до осмотра.

Криминалист после идентификации может дать предварительный вывод:

- имеются огнестрельные повреждения;
- для точной схемы потребуется фиксация/экспертиза.

Точные формулировки «два выстрела» и локализация ранений лучше выдавать отдельным результатом осмотра/заключением, а не мгновенной репликой.

## N310 — фиксация следов `MUST`, реализация после отдельной источниковой проверки

Будущий inspectable-узел.

До подтверждения источниками **не создавать гильзы, пулю, оружие или конкретный след**, которого нет в источниках.

Разрешено создать нейтральную «фиксацию повреждений/следов стрельбы» как документ эксперта, если она не добавляет выдуманный физический предмет.

# Фаза 4. Установление раненого

## N400 — уточнение о раненом `MUST`

Публичные источники устойчиво называют раненого Алексеем Архиповым, но ранние публикации расходятся по месту и тяжести ранения.

Игровой безопасный результат:

- имя: Алексей Архипов;
- он был ранен при попытке остановить/преследовать уходившего преступника;
- точную локализацию ранения сначала не фиксировать.

### FICTION_BRIDGE

Имя можно получить через:

- служебное сообщение из больницы;
- уточнение дежурного по телефону;
- регистрационную запись о госпитализации.

Предпочтительно использовать **служебный телефон**, чтобы существующая механика получила сюжетную функцию.

### Открывает

- карточку `Алексей Архипов`;
- будущую возможность разговора/показаний;
- ветку обстоятельств отхода.

# Фаза 5. Два уходивших человека

## N500 — сведения о втором человеке `MUST`

Источники устойчиво допускают второго участника, но расходятся в деталях: ранняя публикация говорит о двух вошедших в кабинет, поздняя версия — один вошёл, второй наблюдал коридор.

Поэтому первый игровой статус:

`second-man = CLAIM`

Формулировка:

«Есть сведения, что вместе со стрелявшим был ещё один мужчина.»

Только позже версия обвинения может уточнить роль второго человека.

## N510 — направление отхода `OPTIONAL/MUST depending on chosen source`

Не фиксировать конкретный маршрут, пока он не подтверждён дополнительным источником.

Двор рынка уже существует как игровая зона и может получить новые действия после N500, но не должен сам по себе раскрывать направление отхода до получения показаний.

# Фаза 6. Посетитель перед убийством

## N600 — неизвестный посетитель `MUST`

Источники S3/S4 сообщают о предыдущем обращении Малинкина к Жданову, но расходятся в дате (22 или 23 августа).

Игровой канон до лучшего источника:

«Незадолго до убийства к директору приходил молодой мужчина по вопросу торгового места.»

Статус:

`previous-visitor = CLAIM`

Не называть дату точно.

## N610 — установление имени посетителя `MUST / FICTION_BRIDGE`

Публичные статьи не описывают точный следственный механизм, по которому имя было установлено. Допустимая игровая связка:

- журнал посетителей;
- рабочая запись администрации;
- сочетание журнала и показаний сотрудника.

Лучше не делать один документ магическим ответом: запись даёт фамилию/инициал или описание, а компьютер/повторный разговор подтверждает личность.

Результат:

`person-andrey-malinkin = ESTABLISHED as person-of-interest`

Важно: **не «убийца»**, а человек, которого нужно проверить.

# Фаза 7. Проверка Малинкина

## N700 — служебный компьютер `MUST`

После появления имени становится доступен запрос по Малинкину.

Компьютер не должен заранее содержать судебный итог 1996 года. Он работает в историческом времени расследования.

Возможные результаты должны открываться поэтапно:

- основные регистрационные сведения;
- адрес/место проживания, если будет подтверждено источником;
- информация для оперативной проверки.

## N710 — отсутствие / поездка в Сочи `MUST`

S3/S4 сообщают, что Малинкин вылетел в Сочи в день убийства.

Игрок должен получить это не из «волшебной базы», а из последовательности проверки:

`имя → проверка местонахождения → транспортный/оперативный след → Сочи`.

Статус после подтверждения:

`malinkin-sochi = ESTABLISHED within investigation`

Сам факт поездки не доказывает убийство.

# Фаза 8. Задержание и вещественный след

## N800 — задержание 2 ноября `MUST`

Исторически Малинкин задержан 2 ноября 1994 года.

В игровой структуре это поздний рубеж после накопления достаточных оснований.

## N810 — 8 патронов 9 мм `MUST/OPTIONAL evidence`

S2 сообщает об изъятии восьми патронов 9 мм к ПМ при обыске квартиры.

Это первая хорошо подтверждённая кандидатура для настоящей **физической inspectable-улики**.

Предпочтение для 3D-системы:

- коробка/набор из восьми патронов;
- место обнаружения: обыск при задержании;
- статус: вещественное доказательство;
- не называть их «патронами из оружия убийства» без доказательства.

Именно этот предмет лучше использовать как первый полноценный 3D evidence object, а не выдуманную гильзу в кабинете Жданова.

# Фаза 9. Версия Малинкина

## N900 — объяснение торгового конфликта `MUST`

После задержания игрок получает версию Малинкина.

Статус всех его объяснений сначала:

`DEFENDANT_CLAIM`.

Ключевая версия:

- спор из-за торгового места;
- разные суммы оплаты;
- утверждение о конфликте в кабинете;
- утверждение, что Жданов первым достал оружие;
- отрицание заранее подготовленного убийства;
- отрицание разбоя/целенаправленного выстрела в Архипова.

Игрок не должен получать UI-подсказку «он врёт».

# Фаза 10. Документ от 18 августа и противоречие мотиву

## N1000 — распоряжение супрефекта `MUST`

S4 сообщает, что распоряжение от 18 августа запрещало вещевую торговлю на рынке.

После получения документа игрок может сам увидеть противоречие версии о продаже торгового места.

Результаты:

- `aug18-trade-ban = ESTABLISHED`;
- создаётся возможная связь `trade-place-motive ↔ aug18-trade-ban`;
- появляется версия `motive-contradiction = VERSION`.

Не писать автоматически: «значит Малинкин врёт».

# Фаза 11. Ветка «Нико»

Разблокируется после:

- Малинкин установлен;
- версия торгового места получена;
- найдено противоречие распоряжением 18 августа.

## N1100 — конфликт Жданова с «Нико» `MUST for deeper ending`

S4 сообщает о конфликте вокруг павильона фирмы «Нико».

Статус:

`niko-conflict = REPORTED/ESTABLISHED within chosen reconstruction`

## N1110 — оплата квартиры/поездки `MUST for deeper ending`

S4 сообщает, что сотрудники фирмы оплачивали квартиру Малинкина и его поездку в Сочи.

Игрок должен получить это через документы/оперативную проверку, а не одну реплику.

## N1120 — версия заказного убийства `OPTIONAL/FINAL VERSION`

После N1100 + N1110 игрок может создать версию:

`contract-killing = VERSION`

Историческая граница:

- версия допустима;
- связь подозрительна;
- конкретный заказчик не доказан;
- игра не должна превращать подозрение в установленный факт.

# Фаза 12. Домашнее оружие Жданова

## N1200 — находка вдовы `OPTIONAL`

Поздняя ветка по S3:

- ПМ;
- ТТ;
- 296 патронов;
- записка Беспалову о том, что оружие и боеприпасы были найдены на хоздворе рынка.

Эта ветка должна создавать дополнительную неоднозначность, а не простой ответ.

Важно:

`zhdanov-home-weapons != murder-weapon`

Без доказательства нельзя связывать домашний ПМ с оружием, из которого стрелял Малинкин.

# Фаза 13. Финальная версия игрока

Для допуска к финалу обязательны:

- личность погибшего;
- личность Архипова;
- сведения о втором человеке;
- Андрей Малинкин установлен и проверен;
- получена версия Малинкина;
- найдено ключевое противоречие мотиву;
- собран минимальный набор доказательств по Малинкину;
- игрок различает факт и версию о заказчике.

Финальные вопросы:

1. Кто стрелял в Владимира Жданова?
2. Какие обстоятельства подтверждены?
3. Насколько подтверждён мотив конфликта из-за торгового места?
4. Есть ли основания подозревать заказной характер?
5. Можно ли назвать конкретного заказчика установленным?

Исторически корректный сильный финал:

- стрелок — Андрей Малинкин;
- он был осуждён;
- официальная версия мотива существовала, но вызывала серьёзные сомнения;
- признаки возможной связи с «Нико» существовали;
- конкретный заказчик доказан не был.

Судебный итог 1996 года показывается **только после завершения игрового расследования** как исторический эпилог.

# Обязательные узлы для первой полной версии

Минимальная цепочка `MUST`:

`N000 → N100 → N200 → N220 → N230 → N300 → N400 → N500 → N600 → N610 → N700 → N710 → N800 → N900 → N1000 → N1100/N1110 → FINAL`

Физическую улику для вертикального среза предпочтительно строить вокруг `N810` — восьми 9-мм патронов после задержания, потому что этот предмет прямо указан в публичном источнике.

# Защита от сюжетных софтлоков

1. Обязательный документ идентификации нельзя уничтожить/потерять.
2. Если игрок не понимает, как установить личность, криминалист направляет к рабочим бумагам без называния имени.
3. После установления Жданова телефон/дежурный гарантированно может передать уточнение по Архипову.
4. Каждый обязательный свидетель имеет резервный повторный диалог после появления новых вопросов.
5. Удаление пользовательских связей на доске не удаляет сами факты.
6. Нельзя заблокировать выезд с рынка из-за необязательного hotspot-а.
7. Нельзя продвинуться к Малинкину только случайным нажатием на компьютер: сначала нужен игровой lead.
8. Финал проверяет наличие фактов, а не конкретный порядок кликов.
9. Необязательная ветка домашнего оружия Жданова не блокирует основной финал.
10. Если ветка «Нико» нужна для полного финального вывода, она должна иметь минимум два независимых способа напомнить игроку о незакрытом противоречии.

# Что реализовывать следующим

Ближайший кодовый блок:

1. `N220` — документ/служебная карточка на столе;
2. `N230` — подтверждение личности через криминалиста;
3. обновление `investigation-state`;
4. замена карточки «Погибший» на «Владимир Жданов» без дубля;
5. обновление папки и хронологии;
6. после этого — первый настоящий диалог криминалиста и переход к N300.
